# Security model

The root-owned `lumi-eggcracker.service` is the only enforcement component. It reads the root-owned detector catalogue and observes bounded process facts from `/proc`. The control plane has three root-owned Unix sockets: the configured operator may use query and selected-workload sockets; only root can reach the approval-administration socket. A workload account remains a dedicated no-login unprivileged user with no supplementary groups and cannot access any control socket.

An independent root-owned watchdog receives a monotonic authenticated heartbeat from the supervisor and periodically verifies the installed-file manifest. On a lost heartbeat or manifest mismatch it first kills only Eggcracker-owned workload and quarantine cgroups, records a post-containment watchdog receipt, then stops the supervisor. It cannot kill arbitrary host processes during a discovery outage. The supervisor and watchdog have bounded memory, task, CPU, I/O and file-descriptor limits; selected workloads receive explicit PID, memory, CPU, I/O and descriptor limits. Discovery admission is bounded so a burst of matches cannot create an unbounded number of enforcement threads.

For an unapproved complete catalogue match, Eggcracker revalidates PID plus start-time identity, sends `SIGSTOP` through a pidfd, stops descendants, moves the discovered tree into an exact child cgroup delegated to the supervisor, and writes `1` to `cgroup.kill`. Content profiles require two independently validated groups: bounded model content and bounded runtime binary evidence may be in one process or in a bounded related workload (the same unprivileged UID with a live direct parent/child or sibling relation, or one exact Eggcracker-owned workload cgroup). Unrelated same-UID or common-init processes are not joined, and there is no guarantee for escaped, unobserved, containerised or remote workloads. The Safetensors/PyTorch profile does not claim inference; a converter or inspector with both groups is intentionally contained. It proves that cgroup hierarchy is empty before writing the detection receipt. Individual pidfd signals are the initial stop/capture mechanism; direct cgroup-v2 `cgroup.kill` remains the authoritative complete-tree kill primitive.

An approval is an exact root-owned record of a UID, resolved executable device/inode and digest, plus complete argv digest. During discovery, the supervisor hashes the live `/proc/<pid>/exe` descriptor and rechecks PID/start-time and descriptor metadata before using the digest for approval. If the executable cannot be hashed, the candidate remains unapproved and is contained. Approval administration is root-only. Raw process arguments and environment values are not written to approval or detection records.

Heartbeat emission is tied to recent successful discovery completion, not merely to a live worker thread. A blocked or repeatedly failing scan therefore stops heartbeats and lets the independent watchdog apply its bounded fail-closed recovery.

This is not a general sandbox, universal AI detector, host intrusion detector, malware detector, network isolator, credential isolator or EDR replacement. An unapproved workload can evade detection by using an unsupported content/runtime combination; the qualified content path is intentionally narrow and that boundary is documented rather than hidden.
